# 検証レポート

## この文書で分かること

この文書には、公開前に確認したことと、まだ確認していないことを書いています。

ここでの`pass`は、実施した検査に合格したという意味です。プロンプトが必ず良い成果物を作る、または規格に適合するという意味ではありません。

## 調査結果を反映した更新

1.1.0では、`01_CORE_PROMPT.md`の本文を変更せず、生成後に使う評価レイヤを追加し、設定と出力契約の人工的な件数上限・圧縮方針を撤廃しました。

- `17_FORTY_POINT_GATE.md`：40点をGateとして判定するルール
- `18_AI_EVALUATION_PROTOCOL.md`：独立ReviewerとMeta-Judgeの手順
- `19_EXPERIMENT_PLAN.md`：B0/B1/B2比較とPilot計画
- `20_SOURCE_TRUST_AND_HUMAN_AUTHORITY.md`：情報源と人の権限の境界

出力を「無制限」とする変更は、SELaboが項目を削除しないという意味です。モデルのコンテキスト長、APIの応答上限、ファイル生成機能、実行時間を超えた場合の完全出力は、まだ確認していません。

これは仕組みを追加したという意味であり、生成物の品質やGate通過率を実測したという意味ではありません。

## 確認したこと

| 確認した内容 | 結果 | 確認方法 |
|---|---|---|
| ファイルを読み取れるか | pass | すべての収録ファイルを開いた |
| JSONの書き方が正しいか | pass | JSONファイルをプログラムで読み込んだ |
| JSON Schema自体が正しいか | pass | Draft 2020-12のルールで検査した |
| 最小構成のSEモデルがSchemaに合うか | pass | 必須項目だけを持つテストデータで確認した |
| 日本語文章プロファイルがSchemaに合うか | pass | 専用Schemaで検査した |
| Markdownのコードブロックが閉じているか | pass | 開始と終了の数を確認した |
| READMEから参照するファイルが存在するか | pass | ローカルリンクの参照先を確認した |
| 公開版番号が一致しているか | pass | パッケージ、設定、出力契約を確認した |
| マニフェストのハッシュが一致するか | pass | 各ファイルのSHA-256を計算した |

Schemaとは、JSONに必要な項目と形式を定めたルールです。SHA-256とは、ファイルが変わっていないかを確認するための文字列です。

## まだ確認していないこと

次の試験は、まだ行っていません。

- 同じ入力を複数のAIモデルで実行し、結果を比べる試験
- 同じ入力を複数回実行し、結果の安定性を調べる試験
- Cameo、CATIA Magic、Enterprise Architectへモデルを入れる試験
- XMIなど、特定ツール用ファイルの互換性試験
- ISO、IEC、IEEE、JIS、OMG、INCOSEの文書との一項目ずつの適合確認
- 製造設備、ソフトウェア、安全関連など、複数分野での比較
- 日本語の曖昧な表現を、形態素解析などで自動検出する機能
- カスタムGPTやChatGPT Appとしての実運用
- 40点GateのPilot（B0/B1/B2、54実行）
- 独立ReviewerのFalse PassとReviewer間不一致率
- `linguistic_quality`と`semantic_validity`の一致度

## 今後の実験で調べること

同じ入力と設定で3回程度実行し、次を比べます。

- 関係者の候補をどの程度見つけられたか
- ニーズから要求、要求から試験まで、どの程度つながったか
- 曖昧な要求文が何件あったか
- 存在しないIDを参照していないか
- 人が採用、修正、却下した候補の割合
- 出力が途中で切れたり、ZIPが壊れたりしなかったか
- 初稿作成とレビューにかかった時間

## 現在の判断

このパッケージは、実験を始めるために必要なファイルと説明をそろえています。ただし、生成結果の良さ、特定分野での有効性、規格への適合、SysMLツールとの互換性は、今後の実験で確認する必要があります。
