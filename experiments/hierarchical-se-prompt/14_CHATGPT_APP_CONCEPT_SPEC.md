# ChatGPT Appの構想

## この文書の目的

このプロンプトをChatGPT Appにする場合の、最初の設計案です。完成した製品仕様ではありません。

## アプリで実現したいこと

利用者が、対象システムの説明や資料を渡すと、アプリが次を行います。

1. 入力から、対象、範囲、事実、仮定、矛盾を整理する。
2. SEの初稿となる中心JSONを作る。
3. JSON、ID、要求文、日本語、SysMLへの対応を検査する。
4. Markdown、CSV、SysMLモデル仕様を作る。
5. ファイル一覧とハッシュを付けてZIPにする。

## 最初は専用画面を作らない

最初の版は`tool-only`にします。これは、ChatGPTとの会話から外部ツールを呼び出し、結果を返すだけの構成です。

最初から複雑な画面を作らず、ファイル生成と検査が役に立つかを先に確かめます。要求の比較や仮定の採用など、操作が増えた段階で専用画面を追加します。

## MCPツールの候補

MCPは、ChatGPTから外部ツールを呼び出すための仕組みです。処理を五つに分けます。

### 1. `analyze_se_context`

入力された会話やファイルを読み、次を整理します。

- 対象システムの候補
- 対象に含めるものと含めないもの
- 利用者が明示した事実
- 過去にAIが提案した内容
- 矛盾している情報
- 初稿を作るための仮定候補

この処理は、入力を読み取るだけで、利用者のデータを変更しません。

### 2. `generate_se_candidate`

整理した入力と設定を使い、中心となるSEモデルJSONを作ります。

結果には、どのプロンプト、設定、AIモデルを使ったかを記録します。

### 3. `validate_se_candidate`

中心JSONを検査します。

- Schemaに合っているか
- IDが重複していないか
- 存在しないIDを参照していないか
- 要求文が曖昧ではないか
- 日本語のルールに合っているか
- SysMLへ対応付けられるか

意味を変えない表記修正だけを自動化します。数値や責任分担など、意味が変わる修正は人の確認へ回します。

### 4. `build_se_artifact_bundle`

確認済みの中心JSONから、Markdown、CSV、SysMLモデル仕様、検証レポート、ZIPを作ります。

同じJSONと同じ設定からは、同じ内容を作れるようにします。

### 5. `fetch_se_artifact`

作成済みのZIPまたは個別ファイルを取得します。ファイル名、種類、サイズ、ハッシュも返します。

## なぜ処理を分けるのか

すべてを一つのツールで行うと、どこで失敗したか分かりにくくなります。入力整理、生成、検査、ZIP作成、取得を分けると、失敗した処理だけをやり直せます。

## アプリに求める基本ルール

| ID | アプリに求めること |
|---|---|
| APP-NFR-001 | プロンプト、設定、生成日時、中心JSONのハッシュを記録する |
| APP-NFR-002 | 利用者が、自分の生成結果を削除できるようにする |
| APP-NFR-003 | 秘密情報を不要な入力やログへ保存しない |
| APP-NFR-004 | JSON検査に失敗した場合、成功と表示しない |
| APP-NFR-005 | ZIP作成に失敗した場合、作成済みファイルと失敗理由を返す |
| APP-NFR-006 | 同じ入力と設定による再実行を見分けられるようにする |
| APP-NFR-007 | 安全、法律、認証に関する重要事項へ、人の確認が必要だと表示する |
| APP-NFR-008 | 実際のファイル名と、ファイル一覧の名前を一致させる |

## 秘密情報と知的財産

- 公開するプロンプトへ、顧客情報、秘密情報、APIキーを入れない。
- 公開したくない辞書や検査ロジックは、サーバー側へ置く。
- 入力ファイルを保存する期間、目的、削除方法を説明する。
- 規格本文を、許可なく再配布しない。
- AIの出力が、専門家の承認を置き換えないことを表示する。

## アプリの良さを測る数字

- 必要なファイルをすべて作れた割合
- ZIPを正しく開けた割合
- JSONがSchemaに合った割合
- 存在しないID参照の件数
- ニーズから試験までつながった割合
- 要求一件当たりの日本語の問題数
- 人が修正した割合
- 重要なAI推測を見落とした割合
- 同じ入力で、構造がどの程度安定したか
- 初稿作成とレビューにかかった時間

## 公開前に試す入力

- 情報がほとんどない入力
- 詳しい仕様がある入力
- 内容が矛盾する入力
- 複数の対象システムが混ざった入力
- 安全に関係するシステム
- ソフトウェア中心、機械中心、複合システム
- 日本語と英語が混ざった入力
- とても大きいファイル
- JSON検査やZIP作成が失敗するケース
- 添付文書に、AIへ不正な指示を与える文章が含まれるケース
