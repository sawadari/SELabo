# 40点GateとStop Rule

## この文書の役割

この文書は、`01_CORE_PROMPT.md`で作ったSE初稿を、生成とは別に確認するための評価ルールです。コアプロンプトの内容は変更せず、生成後に「人がレビューを始められるか」を判定します。

ここでいう40点は、品質を100点満点で採点した数字ではありません。次の状態に到達したかを表すGate（通過条件）です。

| 状態 | 意味 |
|---|---|
| `below_reviewable` | 重要なつながりや根拠が足りず、レビューを始めにくい |
| `reviewable_40_candidate` | 不確実性を見せながら、人が確認・選択・訂正を始められる |
| `overspecified_beyond_40` | 初稿の範囲を超えて詳細化し、根拠のない設計を固定し始めている |

## 40点で確認すること

次の流れが、候補として追跡できることを確認します。

`Stakeholder → Need → Requirement → Behavior / Structure → V&V candidate`

各項目は、次のいずれかで記録します。

- `sufficient`：レビューに必要な情報がそろっている
- `weak`：候補はあるが、根拠またはつながりが弱い
- `missing`：重要な情報がない
- `over_specified`：初稿として詳細化しすぎている
- `not_applicable`：今回の対象には不要

## Hard Blocker

次のいずれかがある場合、`reviewable_40_candidate`にしません。

- 重要な評価軸が`missing`である
- 未管理の重大な矛盾がある
- AIの推測を、承認済み・正本・ベースラインとして扱っている
- 根拠のない安全、法令、契約、認証の確定主張がある
- 影響の大きい数値を、根拠なしに確定している
- L6/L7で部品型番、正確な公差、詳細アルゴリズム、実装クラスなどを創作している

最後の項目に該当する場合は、`overspecified_beyond_40`とします。根拠が弱いときは、実装パターン候補と人への確認事項で止めます。

## 初期の確認指標

次の数値は国際規格が定めた合格基準ではなく、SELaboのPilot実験で使う仮説値です。実験結果を見て見直します。

| 指標 | 初期値 | 見たいこと |
|---|---:|---|
| 主要NeedからRequirementへのTrace | 80%以上 | 要求の「なぜ」が追える |
| 主要RequirementからBehavior/StructureへのTrace | 80%以上 | 実現方法をレビューできる |
| 主要RequirementからV&V候補へのTrace | 80%以上 | 確かめ方を議論できる |
| 主要要素の`origin`と`status` | 100% | 事実と推測を混同しない |
| 未管理の重大な矛盾 | 0件 | レビュー前の破綻がない |
| 主要Requirementの1要求1義務 | 85%以上 | 要求を判断しやすい |
| 高・重大Findingの確認方法 | 100% | 次の行動が分かる |

数値だけで合否を決めません。Finding、根拠、未確認事項をMeta-Judgeが合わせて判定します。

## Stop Rule

次の条件を満たしたら、初稿の生成を止めます。

1. 上の主要Traceがレビューできる。
2. 不確実性、推測の由来、未確認の数値が表示されている。
3. 重大な矛盾と権限境界の違反が管理されている。
4. 人が答える質問が、確認・選択・承認に絞られている。

この条件を満たした後、60点や80点を目指して自動的に詳細化しません。詳細化は、`reviewable_40_candidate`を人が確認し、別の実験として明示的に開始した場合だけ行います。

## 日本語の二層評価

日本語として読みやすいことと、要求の内容が正しいことは別に評価します。

| 評価層 | 例 | AIだけでの確認 |
|---|---|---|
| `linguistic_quality` | 主語、動詞、条件、単位、1要求1義務、曖昧語 | 比較的しやすい |
| `semantic_validity` | 数値の妥当性、必要性、実現可能性、法規の適用 | 文脈が必要。人の確認を残す |

例えば「非常停止条件を検出したとき、システムは100 ms以内に停止する」は文章の形が整っていても、100 msが正しいとは限りません。次のように記録します。

```text
linguistic_quality: sufficient
semantic_validity: unknown_with_reason
numeric_basis: unsupported
human_confirmation_required: true
```

## 判定結果に残すもの

`quality_summary`へ、少なくとも次を残します。

- `gate_state`
- 各評価軸の状態
- Hard Blockerの有無
- 主要Traceの計算方法と件数
- 重大Findingと最低限の修正候補
- 人が確認する質問
- 使用したGateの版と実行日時

この文書の判定は、承認済み要求、設計承認、規格適合、安全認証の代わりにはなりません。
