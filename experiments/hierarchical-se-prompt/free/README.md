# ChatGPT無料版向け SEデータプロンプト

このディレクトリは、`experiments/hierarchical-se-prompt` の完全版を、ChatGPT無料版でも試しやすくするための軽量実行プロファイルです。

完全版のSE思想を変えるものではありません。無料版では、LLMに意味推論へ集中させ、ファイル生成・ZIP化・JSON Schema検証・PlantUMLレンダリングなどの決定論的処理を実行時から外します。

## 目的

無料版で次の一連の作業を、できるだけデータ分析機能や大量のファイルアップロードに依存せず実行することを目的とします。

```text
人とAIの会話
    ↓
SE_PROMPT_FREE.md
    ↓
SEデータ（テキスト上のJSON）
    ↓
人とAIでレビュー・更新
    ↓
必要なProjectionだけ生成
    ├─ 要求仕様
    ├─ SysML用仕様
    ├─ PlantUML
    └─ 説明・レビュー資料
```

## 完全版との違い

| 項目 | 完全版 | 無料版プロファイル |
|---|---|---|
| 主目的 | 複数成果物を一括生成 | SEデータの意味生成を完走させる |
| 入力ファイル | 複数のPrompt/Profile/Schema | 原則 `SE_PROMPT_FREE.md` だけ |
| 中心成果物 | `10_se_model.json` | SEデータJSONをチャット本文へ出力 |
| 派生成果物 | 一括生成 | 必要時に1つずつ生成 |
| ZIP | 生成する | 生成しない |
| Python/データ分析 | 利用可能なら使用 | 使用しない |
| JSON Schema検証 | 利用可能なら実行 | 実行時には行わない |
| PlantUML | 別工程 | `PLANTUML_PROMPT_FREE.md`で1図ずつ生成 |

## 設計原則

### 1. LLMは意味処理に使う

LLMが担当するのは、次のような非決定論的な意味処理です。

- 利害関係者、ニーズ、シナリオの候補生成
- 要求候補の生成
- 機能・構造・インターフェース候補の生成
- リスク・仮定・検証候補の生成
- 情報間のトレーサビリティ候補の生成
- 抜け・不整合・未確認事項の抽出

### 2. 決定論的処理はLLM実行から外す

次の処理は、無料版ではChatGPTへ要求しません。

- ZIP作成
- 複数ファイルへの分割保存
- Pythonによる加工
- JSON Schema Validatorによる厳密検証
- ID重複のプログラム検査
- PlantUMLレンダリング
- ファイル一括変換

必要な場合は後段のローカルツール、CI、IDE、PlantUML実行環境などで行います。

### 3. 最初から100点を目指さない

無料版でも完全版と同じく、初回はレビュー可能な40点程度のSE初稿を目標とします。

出力量を制御するため、初回は代表候補を優先します。完全な網羅を装わず、追加候補はレビュー後の会話で増やします。

## 使い方

### Step 1: 普通に会話する

対象システムについて、通常のチャットで説明します。

例:

```text
コードレス掃除機についてSE分析したいです。
利用者は一般家庭です。
吸引力だけでなく、運転時間、騒音、安全性、清掃性も重視したいです。
```

要求番号やSysML形式は不要です。

### Step 2: `SE_PROMPT_FREE.md` を貼り付ける

同じチャットで `SE_PROMPT_FREE.md` の本文を貼り付けて実行します。

無料版では、プロンプトをファイルとしてアップロードするより、テキストとして貼り付ける方法を推奨します。

### Step 3: SEデータをレビューする

生成後は、通常会話で修正します。

例:

```text
このSEデータをレビューしてください。
異常シナリオが不足していないか確認してください。
```

```text
バッテリー劣化時の運用を追加してください。
追加した内容に関連する要求、リスク、V&V、relationsも更新してください。
```

### Step 4: 必要な成果物だけProjectionする

例:

```text
現在のSEデータを正として、システム要求仕様だけをMarkdown表で表示してください。
```

SysML/PlantUMLが必要な場合は `PLANTUML_PROMPT_FREE.md` を使用します。

## 推奨する運用

- 1つの対象システムは、可能な限り1つのチャットで継続する。
- SEデータを毎回再アップロードしない。現在の会話内にあるSEデータを更新する。
- 一度に複数の大きな成果物を要求しない。
- 「要求仕様 + SysML + PlantUML + ZIP」のような一括要求を避ける。
- 図は1回につき1図を生成する。
- PlantUMLエラーは、エラーメッセージと該当コードを同じチャットへ貼り、構文修正だけを依頼する。

## Free Runtimeの出力予算

初回SEデータ生成では、原則として次を上限の目安とします。

| 要素 | 初回目安 |
|---|---:|
| stakeholders | 8 |
| needs | 12 |
| scenarios | 8 |
| requirements | 20 |
| functions | 15 |
| structures | 12 |
| interfaces | 12 |
| verification_cases | 12 |
| risks | 10 |
| assumptions | 10 |
| relations | 50 |

これはシステムの意味的な上限ではありません。無料版で初稿生成を完走させるための出力予算です。

重要度が高い候補を先に生成し、追加要素は後続レビューで増やします。

## ファイル

- `SE_PROMPT_FREE.md` : 会話から軽量SEデータを作成する実行用Prompt
- `PLANTUML_PROMPT_FREE.md` : 現在のSEデータからPlantUMLを1図ずつ生成するPrompt

## 完全版との関係

無料版で作成したSEデータは、完全版の `10_se_model.json` と同じ思想を持つ候補意味ソースです。ただし、無料版では出力項目・件数・検査を縮小しています。

より厳密な検証、完全な成果物Bundle、JSON Schema適合確認が必要になった段階で、完全版へ移行してください。
