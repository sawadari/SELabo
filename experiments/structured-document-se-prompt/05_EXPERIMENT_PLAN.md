# 実験3計画

## 仮説

実験1の階層型SEモデルへ企画・要件定義の意味要素と文書ビューを追加すると、企画書と要件定義書の重複記述を減らしながら、目的から受入条件までのトレーサビリティを保った初稿を作れる。

## 比較条件

| 条件 | 内容 |
|---|---|
| B0 | 通常の自由形式で企画書と要件定義書を別々に作る |
| B1 | 実験1の階層型SE初稿生成を使う |
| B2 | 実験1 + 実験3の構造化文書ビュー拡張を使う |

## 共通入力

同じ対象システム、同じ初期説明、同じ利用可能な資料、同じモデル設定を使用します。追加資料を使用した場合は、入力と出典を記録します。

## 観測項目

- 企画目的、KPI、対象範囲の欠落
- 要求から画面、帳票、API、データ、検証、受入への参照率
- 企画書と要件定義書間の名称・数値・単位の不一致
- 未指定値が確定値へ変化した件数
- dangling reference、重複ID、未分類要求の件数
- 人が採用、修正、却下した候補の割合
- 初稿作成時間とレビュー時間

## 成功判定

Schemaと参照整合性の失敗がなく、B2で目的から受入条件までのトレーサビリティが確認でき、B1より文書間の事実不一致が増えないことをMVP成功条件とします。品質向上や業務効果を主張するには、複数対象・複数モデル・人の独立レビューが必要です。

## 未実施として扱う試験

OpenAPI/AsyncAPIの外部仕様が提供されていない場合のlint、Word/PDFのレイアウト、実ユーザーの受入、社内テンプレート適合、業界別標準との完全一致は、実行していない限り`not_performed`と記録します。
