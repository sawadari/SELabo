# VSE実験計画：設計科学による段階的検証

## 1. 研究主張と未立証部分
調査・概念設計はVSEの有用性を直接実証したものではない。「共通データなら判断が改善する」「営業成果が増える」は検証仮説であり、実案件の証拠が必要。Design Science Research（DSR）で人工物を設計・評価し、実務環境ではAction Design Research（ADR）に近い継続的な改訂を行う。

## 2. 研究課題
- RQ1：情報の由来/状態/意味を一般的LLM利用より正確に維持できるか。
- RQ2：戦略代替案と重要な反証の発見率が改善するか。
- RQ3：人によるレビュー・意思決定の時間と認知負担を減らせるか。
- RQ4：根拠のない事実昇格・架空ROI・因果過大主張を減らせるか。
- RQ5：実営業・企画の採否、顧客検証・実行結果に寄与するか。
- RQ6：変更後の仮説・戦略・施策・KPIの整合性を維持できるか。

## 3. 比較条件
- B0：一般的な『マーケティング戦略を考えて』というLLM依頼。
- B1：前段のMarketing Data Prompt v0.1（SE類推型）。実行する場合は当該版を確保する。
- B2：本VSE 1.0.0（同一生成モデル、同一入力条件）。
- B3：B2の出力を独立Reviewerで評価・修正する条件。レビュー費用を必ず合算する。

生成条件：3領域（製造業B2Bコンサル/デジタルサービス/製品企画）×2入力量（少量/中量）×4条件×3反復=72試行を初期Pilot案とする。この数字は探索用であり、統計的検出力の保証ではない。

## 4. 主指標
| 指標 | 定義・注意点 |
|---|---|
| Gate通過率 | 40点Gate通過数/全数（厳格Gateが分母を偏らせないよう要注意） |
| 情報源対応の正解率 | サンプルの原文から人が付けた正解ラベルと比較 |
| Trace coverage | 対象とする関係のうち解決可能かつ意味のある関係の比率 |
| 反証可能性 | 重要仮説に具体的な観測・反証条件がある割合（人の確認が必要） |
| 代替案の妥当性 | 同じ問題/判断基準で比較可能かを人が匿名採点 |
| False Pass | AIがGateを通過させた成果で人がHard Blockerを発見した割合 |
| 人のレビュー時間 | 課題発見から選択肢/質問を確認するまでの時間 |
| 生成・評価コスト | 実行時間、トークン、推定APIコスト、再実行数 |
| 実務評価 | 継続利用、意思決定の実行、実顧客の反応。市場成果と因果効果は別検証 |

## 5. 研究のGate
G1: JSON/ID/参照の技術検査。G2: 実在の専門家による内容評価。G3: 実利用者による業務上の評価。G4: 実案件による成果への寄与の検証。G1合格はG2～G4の代替にならない。

## 6. 盲検化と事前登録
入力ケース、モデル識別子、プロンプト版、評価者、評価基準、失敗定義を実験前に固定する。比較する出力は条件名を隠して提示する。評価者間不一致を記録する。成功例だけ公開しない。

## 7. プライバシーと再現性
顧客情報は匿名化・権限確認する。実験ログには日時、入力hash、モデル/温度、プロンプト版、Schema版、出力hash、J-Tier、Gate、時間、費用を保存。第三者が再実行できる架空ケースを同梱する。

## 8. 完了条件
VSEが研究として有効と主張するのはG2以降の人の評価と、B0/B1/B2/B3比較の結果が揃ってからとする。売上改善の因果効果はG4で別途扱う。
