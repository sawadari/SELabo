# VSE意思決定・検証・継続学習プロトコル

## 1. 最初の一回
会話と資料から候補JSONを構築。要素にID、出自、状態、根拠、検証計画を持たせる。最初の成果は最適戦略ではなく、人が比較・反証・選択できるレビュー対象とする。

## 2. 人による判断
候補に対して`adopt`（採用）、`revise`（修正）、`reject`（却下）、`defer`（保留）を選び、理由・責任者・日時・影響IDを記録する。`approved`や`user_confirmed`は人間が実際に承認を行ったときのみ付与する。

## 3. 情報更新の処理順
1. 新しい入力を`source_fragments`に追加し、既存IDのソースを勝手に書き換えない。
2. 観測・主張・推測の分類と信頼性・同意を確認する。
3. 新旧の内容の一致・競合・失効を判定し、曖昧なものはFindingへ登録。
4. 変更対象要素の直接関係を列挙し、二次の依存・意思決定・施策・評価への影響を探索する。
5. 根拠が崩れた仮説は`stale`にし、採用済み案については見直しの推奨を作る。AIが自動で承認取消・決裁変更を行わない。
6. 正本の更新後にMarkdown/CSV/図仕様を再投影し、ファイル整合性を検査する。

## 4. 因果仮説の更新
実験データが得られたら、仮説の予測、実験デザイン、比較群、バイアス、効果の推定範囲を記録する。短期の観測上の変化は因果確定ではない。実験が中止・失敗した場合もログに残す。

## 5. 意思決定のストップ条件
重要な代替案と観測方法がレビュー可能になった時点で40点初稿を停止。顧客の承認や実測数値がない場合も「未確定」のままにする。追加の施策実行は明示された人間の承認後のみ。

## 6. AI自身の改善
生成ルールやチェック規則の変更は、変更理由、失敗事例、評価結果、互換性を記録し、比較実験を通して適用する。良い出力が得られたからといって、当該変更の一般的有効性を断定しない。
